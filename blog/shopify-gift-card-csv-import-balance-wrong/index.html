Re-Importing Your Shopify Gift Card List? Here's Why Balances Can Come Out Wrong

Short answer: Shopify's gift card export only keeps the last four characters of each code, and Shopify has no native way to re-import a CSV to create gift card products at all — that pushes merchants toward third-party bulk tools, and at least one of those tools documents that its "bulk update" sets a balance to whatever value is in the file rather than adding or subtracting from it. Re-import a file with stale numbers, and you can silently overwrite a correct, current balance with an old one.

Who runs into this

This usually shows up during a platform migration, a re-launch after a long gap, or when a merchant tries to clean up a messy gift card list by exporting it, editing it in a spreadsheet, and importing it back. It feels like routine data hygiene. The problem is that "routine" is doing a lot of work in that sentence — gift card balances are live, moving numbers, and a CSV round-trip treats them like static records.

Why Shopify's own export isn't a safe round-trip source

Shopify's gift card export exists mainly for record-keeping, not for re-import. Two limitations matter here:

  • The exported code is truncated. Shopify's own export keeps only the last four characters of each gift card code, the same way a receipt masks most of a credit card number. That's enough to identify a card in a report, but not enough to safely re-create or re-match it programmatically.
  • There's no native CSV re-import for gift cards. Shopify doesn't offer a built-in way to take a gift card CSV and create or update gift card products from it. The Gift Card API that would let an app do this programmatically is Plus-only — standard-plan merchants who want bulk gift card tooling at all are pushed toward third-party apps.

Where the balance actually goes wrong

Once a merchant is relying on a third-party app for bulk gift card work, the exact behavior of that app's "bulk update" feature matters a lot more than most merchants realize. At least one gift card app's own documentation states plainly that its Bulk Update action sets the balance to the exact value in the uploaded file — it does not add to or subtract from whatever balance is currently on record. That's a meaningful distinction:

  • An adjustment (add $20, subtract $5) is safe to apply against a balance that's been changing since you last exported it.
  • An overwrite (set balance to $20) is only safe if the file you're uploading reflects the balance at this exact moment — not an hour ago, not yesterday, and not from before a customer spent part of the card.

The failure mode is quiet rather than dramatic. A merchant exports a gift card list to clean up formatting or merge a legacy platform's data, a customer redeems part of a card's value in the meantime, and then the "cleaned up" file gets re-imported — resetting that card back to its pre-redemption balance. Nothing errors out. The balance is simply wrong again, and the first sign is usually a confused customer or a support ticket, not a visible failure in the import itself.

Who this hits hardest

  • Platform migrations. Merchants moving a legacy gift card program onto Shopify, where a one-time CSV migration is often the only practical path.
  • Multi-source consolidation. Stores reconciling gift card records that exist across more than one system before standardizing on Shopify's native gift cards.
  • Bulk corporate issuance. Programs that issue many cards at once and later try to bulk-adjust or correct a batch of them in one pass.

How to avoid overwriting a correct balance

  1. Check whether a bulk tool adjusts or overwrites before trusting it with a re-import — read the app's own documentation for the specific action you're about to run, not just its marketing page.
  2. Export immediately before you import, not days earlier, so the file you're uploading reflects current balances rather than a stale snapshot.
  3. Avoid re-importing a file that covers cards customers could have used in the meantime. If any time has passed, re-export fresh rather than reusing an older file, even a "small edit" of one.
  4. Spot-check after the import, comparing a handful of balances against what they should be, before assuming the bulk action did what you expected.

Frequently asked questions

Can I safely re-import Shopify's own gift card export file?

Not as a balance-update mechanism. Shopify's export truncates each code to its last four characters and isn't designed to be re-imported to update gift cards. Any bulk update has to go through a third-party app, and you need to know whether that app's update action adjusts or overwrites a balance.

Does Shopify have a native bulk gift card import feature?

No. There's no built-in way to create or update gift cards in bulk from a CSV. The programmatic path — the Gift Card API — is restricted to Shopify Plus, which is why standard-plan merchants doing bulk gift card work rely on third-party apps instead.

How do I know if a bulk-import tool will overwrite a balance instead of adjusting it?

Check that specific app's own documentation for the exact action you're about to run — the terminology varies, but the distinction between "set this value" and "add or subtract this value" is the one that matters. When in doubt, test on a single card with a known balance before running a bulk action against your whole list.
