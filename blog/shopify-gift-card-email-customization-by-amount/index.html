How to Safely Customize Shopify Gift Card Emails by Purchase Amount

Short answer: Showing a different image or message in a gift card notification email based on how much was purchased is possible with Liquid conditionals on the gift_card.initial_value variable, but a broken {% endif %} or an unscoped variable reference can silently stop the email from sending at all — not just render wrong. Test each value tier in isolation before trusting the template with real orders.

A real request that broke gift card delivery

A merchant posted in the Shopify Community after trying to show a different image in the gift-card notification email depending on the amount purchased — three tiers, roughly $1,000–2,000, $2,000–3,000, and $3,000+ — using Liquid conditionals in the notification template. The result: "It stopped sending anything the customer and its not showing the right picture." A community member suggested checking for unclosed {% endif %} tags and isolating the gift_card_value variable, but the thread ends with no confirmed fix. That's a meaningfully worse failure than a cosmetic bug — a gift card that never arrives is a support ticket and a bad first impression on a purchase meant to feel like a gift, not a chore.

Why this template is riskier to edit than it looks

Shopify's gift card notification email is a Liquid template like any other, but it's rendered at send time for every gift card purchase — a syntax error doesn't just break the visual layout, it can prevent the email from rendering (and therefore sending) at all. Two mistakes account for most reported breakage:

  • Unbalanced {% if %} / {% endif %} blocks. Three value tiers usually means three conditions, and it's easy to lose track of matching each {% if %} or {% elsif %} to its closing tag once the template has more than one branch.
  • Referencing the value variable outside its available scope. The variable that holds the gift card's value needs to be referenced exactly as Shopify's template context exposes it in that specific template — a typo'd or wrongly-scoped reference can fail silently rather than throwing a visible error.

A safer way to structure the conditional

  • Duplicate the template before editing, not after something breaks. Shopify lets you preview notification templates — save a working copy of the original before adding any conditional logic, so there's an immediate rollback if delivery stops.
  • Build tiers with {% elsif %}, not separate stacked {% if %} blocks. A single {% if %}...{% elsif %}...{% elsif %}...{% else %}...{% endif %} chain has exactly one closing tag to track, versus three independent blocks that are each a chance to mismatch a tag.
  • Test every tier with an actual test order, not just a template preview. A template preview doesn't always catch what happens when a real order triggers the notification job — send a real test gift card at each price tier before relying on the template in production.
  • Keep a plain default branch. An {% else %} that renders the original, non-tiered design ensures that any value that doesn't cleanly match a tier boundary still produces a working, deliverable email rather than an edge case that falls through and breaks.

Where Gift Check Pro fits

Gift Check Pro doesn't edit or replace Shopify's native gift card notification template — that customization has to happen in the theme's notification settings directly. What it solves is what happens after that email lands: a self-serve way for the recipient to check their balance going forward, independent of whether the original email's design tier rendered correctly or not, so a template experiment doesn't become the only place a customer can find out what their card is worth.

Frequently asked questions

Can I preview how a value-tiered gift card email will look before it goes live?

Yes — Shopify's notification template editor includes a preview mode. Use it to check each tier's rendering, but still send a real test order per tier before trusting it in production, since some failures only appear when the actual notification job runs.

What's the safest way to roll back if a template edit breaks delivery?

Keep the original, unedited template content saved separately before making changes, so you can paste it back in immediately rather than debugging live while gift card emails are failing to send.

Does this affect the gift card's actual balance or code, not just the email?

No — this is purely about the notification email's presentation. The gift card's code and balance are generated independently of the email template and aren't affected by a broken conditional.
